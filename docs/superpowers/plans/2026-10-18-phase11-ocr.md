# Phase 11: Recognise Text on Scanned Pages (OCR) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** "Recognise text" finds the words on scanned pages on the device with ML Kit. It puts them into the page as invisible text, so search, selection and copying work, in TilePDF and, once saved, in any reader.

**Architecture:**
- **Recognising.** A new `core:ocr` module wraps ML Kit's bundled Latin recogniser behind `TextRecognizer`.
- **Turning results into page words.** `recognizedWords` (JVM) turns ML Kit's pixel boxes into page words (`OcrWord`: text + top-left point quad). It knows the render scale and the quarter turn the page was shown with.
- **Showing the words at once.** The reader adds the words to its open document in memory (`PdfDocument.addRecognizedText`) and drops that page's cached text. Search and selection then see them at once.
- **Keeping them until saved.** The words wait in a new Room table, `recognized_text` (one row per page), until the save writes them.
  - The draft row would be too big: Room's cursor window is 2 MB.
- **Saving.** The save writes them with PDFium:
  - one invisible text object per word;
  - the Noto Sans subset from phase 10 as an embedded CID font;
  - a `TilePdfOcr` content mark.
  - The mark tells "already recognised" and lets saving skip pages the file already has.

**Tech Stack:** ML Kit `com.google.mlkit:text-recognition:16.0.1` (bundled, on device), PDFium edit API (`FPDFText_LoadFont`, `FPDFPageObj_CreateTextObj`, `FPDFTextObj_SetTextRenderMode`, `FPDFPageObj_AddMark`, `FPDFPage_GenerateContent`), Room v8, Hilt, Compose.

**Spec:** the roadmap at `~/.claude/plans/nifty-yawning-lark.md`, phase 11. It is stacked on phase 10 for the font asset.

## Global Constraints
- **Nothing leaves the device.**
  - The manifest removes `INTERNET`, so nothing can be sent. `ACCESS_NETWORK_STATE` stays: WorkManager needs it, and it only reads the network state.
  - `checkReleasePermissions` stays green.
  - Recognition must work in airplane mode.
- **ML Kit's native libraries must be 16 KB page aligned**, as Play requires. Check with `llvm-readelf -l` in the APK.
- **OCR only when asked.** Opening a document never runs recognition.
- **The look of the page never changes.** Text render mode is invisible (3).
- **Strings in EN and TR.** Accessibility labels on new controls.

## Review Focus
- **A page turned with the reader's rotate:** words still land on the right place after saving. Covered by `RecognizedWordsTest` with quarter turns.
- **Cancelling midway:** pages done so far are kept; no half page.
- **A page the file already recognised (the `TilePdfOcr` mark):** not written twice when saving, and "Recognise" says the page is done.
- **A huge scanned book (200 pages):** rows per page, progress shown, memory bounded (one bitmap at a time, capped at 2500 px).
- **Save as copy, share and print** include the recognised text.

### Task 1: Page words from recognition results (JVM)
**Files:**
- Create: `core/model/.../model/OcrWord.kt`: `data class OcrWord(val text: String, val quad: List<PdfPoint>)`.
  - Four corners: top-left, top-right, bottom-right, bottom-left of the word as read, in page top-left points.
- Create: `core/ocr/.../RecognizedWords.kt`: `fun recognizedWords(words: List<PixelWord>, scale: Float, rotation: Int, pageWidth: Float, pageHeight: Float): List<OcrWord>`.
  - `PixelWord(text, corners: List<PdfPoint>)` comes from ML Kit's `cornerPoints`.
  - The bitmap was rendered with the page turned by `rotation` (0/90/180/270) and scaled by `scale`; each corner is mapped back to the unturned page.
  - Blank texts are dropped.
- Test: `RecognizedWordsTest`:
  - `unturnedPageDividesByScale`;
  - `quarterTurnMapsBackToThePage` for 90, 180 and 270, checked against `PageViewTransform`;
  - `blankWordsAreDropped`.

### Task 2: The recogniser module
**Files:**
- Create the module `core:ocr` (Android library plus Hilt):
  - `TextRecognizer` interface: `suspend fun recognize(bitmap: Bitmap): List<PixelWord>`;
  - `MlKitTextRecognizer`, using `TextRecognition.getClient(TextRecognizerOptions.DEFAULT_OPTIONS)`. It walks blocks, then lines, then elements; `await` comes from `kotlinx-coroutines-play-services`, if it is already in the catalog, otherwise from a `suspendCancellableCoroutine` wrapper;
  - a Hilt binding.
- Modify:
  - `gradle/libs.versions.toml` (ML Kit);
  - `settings.gradle.kts`.

Expected:
- `assembleRelease` and `checkReleasePermissions` are green.
- `llvm-readelf -l` shows ML Kit's `.so` `LOAD` alignment as 0x4000.

### Task 3: Invisible text in PDFium
**Files:**
- Modify: `pdfium_jni.cpp`. Add:
  - `nativeAddRecognizedText(doc, page, texts: Array<String>, quads: FloatArray): Boolean`;
  - `nativeHasRecognizedText(doc, page): Boolean`.
  - The font is loaded once per document from the fallback font bytes that `nativeInit` keeps.
  - For each word: a text object at font size 1. Its matrix maps the font's em box (baseline at the descent) onto the word's quad, mapped to PDF space like ink points. It gets render mode `INVISIBLE` and the mark `TilePdfOcr`.
  - Then `FPDFPage_GenerateContent` runs, and the page's cached text page is dropped.
- Modify: `PdfDocument`, `PdfiumDocument`, `EditablePdfDocument` and `PdfiumEditableDocument`: add `addRecognizedText(pageIndex, words)` and `hasRecognizedText(pageIndex)`.
- Test: `core/pdf/src/androidTest/.../PdfiumOcrWriteTest`:
  - add words to `sample.pdf` page 0, save and reopen;
  - `pageText` contains them near their quads;
  - the page renders the same as before (equal pixels);
  - `hasRecognizedText` is true.

### Task 5: Recognising from the reader
**Files:**
- Create: `feature/reader/.../TextRecognition.kt`, holding `RecognitionProgress(done, total)` and the pure function `pagesToRecognize(scope, current, pageCount, hasText)`. "This page" or "all pages without text".
- Modify: `ReaderViewModel`:
  - `onRecognizeText(allPages)`, `onRecognitionCancelled`;
  - a job, one page at a time:
    1. render at `min(2500 / longSide, 4)` px per point with the page's rotation;
    2. `recognizer.recognize`;
    3. `recognizedWords`;
    4. `repository.setRecognizedText`;
    5. `document.addRecognizedText`;
    6. drop the page from the text cache;
    7. update progress.
  - Pending pages are added to the open document on open, like pending form values.
- Modify: `ReaderScreen` and `ReaderUiState`:
  - ⋮ "Recognise text" opens a dialog: this page / all pages without text (N);
  - a progress bar with "Recognising text 3/12" and Cancel;
  - a quiet chip, "No text on this page · Recognise", while the shown page has no text and isn't being recognised.
- Strings: EN + TR.
- Tests (JVM, fake recogniser and fake document):
  - `pagesToRecognizeTest`;
  - `ReaderViewModelTest` additions:
    - recognising stores words and adds them to the document;
    - cancel keeps the finished pages;
    - progress counts.
