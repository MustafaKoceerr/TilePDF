# Phase 5a — Annotation Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PDFium reads TilePDF's own annotations and other apps' annotations, writes TilePDF's (highlight, underline, strikeout, ink, note), deletes any markup annotation (ours or foreign, with its popup), and saves incrementally so other viewers can display the result.

**Architecture:** A pure Kotlin annotation model lives in `core:model`. Our annotations carry `/NM = tilepdf-<uuid>`. The reader opens documents as before, and its pages hide our annotations in memory so Compose can draw them (5c). The reader can also hide a deleted foreign annotation in memory (and show it again on undo). A separate `EditablePdfDocument` from `PdfEngine.openForEditing` applies a diff of own annotation ids plus foreign deletions, generates appearance streams by rendering touched pages once, and saves incrementally to a file. The diff itself is a pure function with JVM tests. Everything that crosses JNI is covered by instrumented tests.

**Tech Stack:** as before; PDFium `fpdf_annot.h`, `fpdf_save.h` (chromium/8076, all functions used here verified in the headers).

**Spec:** `docs/superpowers/specs/2026-10-16-tilepdf-v1-design.md` (Açıklama, Açıklama kayıt akışı) and `docs/superpowers/specs/2026-10-17-phase5-annotations-design.md` (decisions, split, differences from the spec)

## Global Constraints

- All PDFium calls stay on the single PDF dispatcher under the document's mutex, as `PdfiumDocument.withDocument` does today.
- Coordinates in the model are top-left PDF points, as everywhere else (`PdfRect`). JNI converts with the existing `PageToTopLeft` / `TopLeftToPage` (×64 device scheme), so rotated pages round-trip.
- Our id prefix is exactly `tilepdf-`. Any annotation whose `/NM` doesn't start with it is foreign: never modified, only removed when the user deleted it. A foreign key is its `/NM` when it has one, else `#<index>` (its index among the page's annotations in the file as opened). Foreign `#index` keys are resolved to annotations before anything on that page changes.
- Deletable (markup) subtypes: Text, FreeText, Line, Square, Circle, Polygon, PolyLine, Highlight, Underline, Squiggly, StrikeOut, Stamp, Caret, Ink, FileAttachment. Link, Popup and Widget annotations are never listed. Removing an annotation also removes its linked `/Popup` (`FPDFAnnot_GetLinkedAnnot(annot, "Popup")`).
- The hidden flag is set only on documents opened by `PdfEngine.open` (reader). `openForEditing` never hides anything, and a reader document is never saved.
- Strings cross JNI as UTF-16 (`FPDF_WIDESTRING`), never `NewStringUTF` on PDF bytes.
- Test rules: JVM unit tests drive TDD (`./gradlew :core:pdf:testDebugUnitTest --tests "*X*"`). JNI can only be checked on a device. Instrumented tests are written in each task and run with `./gradlew :core:pdf:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=<fqcn>` **only if the user approved running them for this plan**; otherwise they are written and run once at the end with the user's OK. If they fail, report the cause and ask; don't loop on fixes.
- No new binaries in the repo: the fixture is generated by `tools/generate_test_pdfs.py`, deterministically, and existing fixtures stay byte-identical.

## Review Focus

1. **Rotated page (`/Rotate 90`)**: an annotation added at a top-left point reads back at the same point, and its appearance is drawn there. Task 4 `rotatedPageRoundTrips`.
2. **Foreign annotations survive a save** untouched (count, subtype, `/NM`) unless the user deleted them, even when ours on the same page change; deleting one takes its popup along, and indexes don't shift onto the wrong annotation. Task 4 `foreignAnnotationsAreKept`, `removingForeignRemovesItsPopup`, `removingUnnamedForeignByIndex`.
3. **Another viewer shows what we saved**: Android's `PdfRenderer` renders the saved highlight (appearance stream present). Task 4 `platformRendererShowsSavedHighlight`.
4. **Turkish text in a note** (`"Not: çğışöü İ"`) round-trips exactly. Task 4 `noteTextRoundTrips`.
5. **The hidden flag never reaches a file**: own annotations in a saved file are visible to other viewers. Task 4 `savedOwnAnnotationsAreNotHidden`, and Task 3 `editingDocumentDoesNotHide`.

**Interfaces:**
- `data class PdfPoint(val x: Float, val y: Float)` (top-left points).
- `sealed interface Annotation { val id: String; val pageIndex: Int; val color: Int /* ARGB */ }`
  - `data class TextMarkup(id, pageIndex, color, val kind: MarkupKind, val rects: List<PdfRect>, val text: String)`; `enum class MarkupKind { Highlight, Underline, StrikeOut }`. Each rect is one line of selected text.
  - `data class Ink(id, pageIndex, color, val widthPt: Float, val strokes: List<List<PdfPoint>>)`
  - `data class Note(id, pageIndex, color, val at: PdfPoint, val text: String)`. `at` is the icon's top-left.
- `data class ForeignAnnotation(val pageIndex: Int, val key: String, val subtype: Int /* FPDF_ANNOT_* */, val bounds: PdfRect, val contents: String, val inkStrokes: List<List<PdfPoint>>)`. `inkStrokes` is empty unless subtype is Ink, and is used by the eraser in 5c. Only deletable subtypes are produced.
- `data class PageAnnotations(val own: List<Annotation>, val foreign: List<ForeignAnnotation>)`
- `const val OWN_ANNOTATION_PREFIX = "tilepdf-"`; `fun newAnnotationId(): String` (prefix + random UUID); `fun isOwnAnnotationId(id: String?): Boolean`.
- `data class ForeignRef(val pageIndex: Int, val key: String)`.
- `data class AnnotationChanges(val removals: Map<Int, Set<String>>, val additions: List<Annotation>, val foreignRemovals: Map<Int, Set<String>>)` with `val isEmpty`; `fun annotationChanges(existing: Map<Int, Set<String>>, wanted: List<Annotation>, existingForeign: Map<Int, Set<String>>, removedForeign: Set<ForeignRef>): AnnotationChanges`. `existing` is page → own ids in the file. Ids in both are left alone. Foreign removals keep only refs that still exist in the file. Pages with nothing to remove are absent from both maps.

### Task 3: Read annotations; hide ours in the reader

**Interfaces:**
- `internal class NativeAnnotation(val subtype: Int, val id: String?, val contents: String?, val color: Int, val width: Float, val rect: FloatArray /* top-left l,t,r,b */, val points: FloatArray, val pathSizes: IntArray, val hasAppearance: Boolean)`. `points` is quads as 4 top-left corner pairs each (markup), all ink paths concatenated (with `pathSizes` giving the point count per path), or empty.
- `external fun nativePageAnnotations(document: Long, index: Int): Array<NativeAnnotation>?` (null if the page can't load).
- `suspend fun PdfDocument.setForeignHidden(pageIndex: Int, key: String, hidden: Boolean)` sets or clears `FPDF_ANNOT_FLAG_HIDDEN` on that foreign annotation in memory (a reader document is never saved), so the next render leaves it out. Native: `nativeSetForeignHidden(doc, index, key, hidden): Boolean`.
- `suspend fun PdfDocument.annotations(pageIndex: Int): PageAnnotations`. Own annotations are mapped by subtype: Highlight/Underline/StrikeOut → `TextMarkup` (each quad → its bounding `PdfRect`; `text` = `/Contents` or ""); Ink → `Ink` (`widthPt` = border width, default 1); Text → `Note` (`at` = rect top-left). Own ids with other subtypes are skipped. Foreign annotations of a deletable subtype become `ForeignAnnotation(key = /NM or "#index", bounds = rect, contents = contents ?: "", inkStrokes)`. Other subtypes are skipped.
- Hiding: on load, when `hideOwnAnnotations`, every annotation whose `/NM` starts with `tilepdf-` gets `FPDF_ANNOT_FLAG_HIDDEN` added (`FPDFAnnot_GetFlags | HIDDEN`, `SetFlags`). Annotations are closed with `FPDFPage_CloseAnnot`.

### Task 4: Write annotations and save incrementally

**Files:**
- Create: `core/pdf/src/main/java/com/mustafakoceerr/tilepdf/core/pdf/EditablePdfDocument.kt`, `PdfiumEditableDocument.kt`; `core/pdf/src/androidTest/.../PdfiumAnnotationWriteTest.kt`
- Modify: `pdfium_jni.cpp` (include `fpdf_save.h`; write natives; `FPDF_FILEWRITE` writing to an fd), `PdfiumNative.kt`, `PdfEngine.kt` (+ `openForEditing`), `Pdfium.kt`; fakes implementing `PdfEngine`

**Interfaces:**
- `interface EditablePdfDocument : Closeable { val pageCount: Int; suspend fun ownAnnotationIds(pageIndex: Int): Set<String>; suspend fun foreignKeys(pageIndex: Int): Set<String>; suspend fun apply(changes: AnnotationChanges); suspend fun saveIncremental(target: File) }`
- `suspend fun EditablePdfDocument.write(wanted: List<Annotation>, removedForeign: Set<ForeignRef>): Boolean` scans every page's own ids and foreign keys, applies `annotationChanges`, and returns false if there was nothing to do (nothing applied).
- `PdfEngine.openForEditing(uri: Uri, password: String? = null): EditablePdfDocument`, with the same exceptions as `open`. It opens with `hideOwn = false`, and the file descriptor stays open until `close`.
- Natives (all page indices are checked in Kotlin first):
  - `nativeOwnAnnotationIds(doc, index): Array<String>?`
  - `nativeForeignKeys(doc, index): Array<String>?` (keys of deletable foreign annotations).
  - `nativeRemoveAnnotations(doc, index, ownIds: Array<String>, foreignKeys: Array<String>): Boolean`. It resolves every target (own by `/NM`, foreign by `/NM` or `#index`) to an index first, adds each target's linked popup, and removes them in descending index order.
  - `nativeAddMarkup(doc, index, subtype, color, quads: FloatArray /* top-left, 8 per rect: TL, TR, BL, BR */, id, contents): Boolean`. Sets `/Rect` to the union of the quads in page space.
  - `nativeAddInk(doc, index, color, width, points: FloatArray, pathSizes: IntArray, id): Boolean`. One `FPDFAnnot_AddInkStroke` per path, `FPDFAnnot_SetBorder(0, 0, width)`, `/Rect` = path bounds inflated by width.
  - `nativeAddNote(doc, index, color, x, y, id, contents): Boolean`. `/Rect` is 24×24 pt from the top-left point.
  - `nativeGenerateAppearances(doc, index)` renders the page once into a 1×1 bitmap with `FPDF_ANNOT`, so PDFium writes `/AP` for annotations missing one.
  - `nativeSaveIncremental(doc, fd): Boolean` (`FPDF_SaveAsCopy(..., FPDF_INCREMENTAL)`; the write callback loops `write` on EINTR).
  - All set `/NM` and `/Contents` via `FPDFAnnot_SetStringValue` (UTF-16LE from `GetStringChars`), color via `FPDFAnnot_SetColor` with alpha from ARGB.
- `apply` removes first (own and foreign together, per page), then adds, then generates appearances for every touched page.
